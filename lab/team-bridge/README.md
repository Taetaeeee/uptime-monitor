# 실제 Paseo 팀 연결 (로컬 1차)

개인 PC에서 실제 팀을 조회하고, 기존 팀장에게 **읽기 전용 조사·설계 요청**을 전달합니다. 전체 세션 원문을 긁어오지 않고 담당이 선택해 게시한 작업 요약만 표시합니다. 기존 규칙 조사와 실제 팀은 별도 화면입니다.

## 실행

Node.js 22 이상과 로그인되어 있는 Paseo CLI가 필요합니다. 제품 OpenAI API 키와는 별도입니다. 조회는 모델을 호출하지 않지만 작업 요청은 기존 Claude·GPT 계정 사용량을 쓸 수 있습니다.

```powershell
cd C:\Users\User\Projects\uptime-monitor
# 최초 설정: 아래 예시를 lab/.runtime/team-bridge/bindings.json에 복사하고 실제 세션 UUID로 채웁니다.
# 현재 PC에 준비한 bindings.json은 유지하세요. Git에는 넣지 않습니다.
node lab/team-bridge/server.mjs
# 다른 터미널
Invoke-RestMethod http://127.0.0.1:18912/api/teams
Start-Process http://127.0.0.1:18912/agents.html
```

`bindings.example.json` 형식을 사용합니다. UI/AI 팀마다 팀장·A·B를 연결하고 C·D·E는 같은 UUID를 지정할 수 있습니다. 모델과 상태는 설정의 예시값이 아니라 `paseo inspect --json`에서 조회합니다. 다른 프로젝트 cwd이거나 보관된 세션은 오프라인으로 처리합니다. 세션 이름만 같다고 자동으로 재연결하지 않습니다. 새 서버로 옮기면 그 서버의 세션을 확인해 매핑을 다시 만듭니다.

CLI 경로가 PATH에 없으면 `PASEO_CLI_COMMAND`에 설치된 공식 실행 파일 경로를 설정합니다. 브리지는 기존 로그인과 권한을 사용하며 자격증명을 복사·배포하거나 권한 모드를 변경하지 않습니다.

- 팀 화면: `http://127.0.0.1:18912/agents.html`
- 실측 관측: `http://127.0.0.1:18911/`
- 고정 규칙 조사: `http://127.0.0.1:18911/rules.html`
- Docker와 브리지는 별도 프로세스입니다. `node lab/start.mjs --build`는 Docker만 시작합니다.

## 작업과 상세

팀장이 왼쪽, A~E가 오른쪽인 역할 그래프입니다. 생성 부모 관계를 바꾸는 기능이 아닙니다. 노드 또는 작업의 상세에서 요약·대화·실행 기록·변경 제안을 봅니다.

요청은 팀장이 idle이고 다른 담당이 실행·승인 대기·조회 불가가 아닐 때 접수합니다. 종료된 담당은 다시 열지 않고 위임 대상에서 제외합니다. 공통 C/D/E 때문에 양 팀 합쳐 한 건만 진행합니다. 웹 요청의 멱등 키를 저장하며, 재시작 후 미완료·전달 불명 작업은 자동 재전송하지 않습니다. 웹 추적 닫기는 실제 세션 중단이 아닙니다. 기존 Paseo에서 권한 승인·중단을 처리합니다. CLI의 idle 확인과 실제 send는 원자 연산이 아니므로 사람이 같은 세션에 동시에 지시하지 않아야 합니다.

팀장에게 역할별 기존 세션 UUID와 공개 요약 게시 방법을 전달합니다. 담당은 필요에 따라 직접 위임하고 `report.mjs`로 지시 요약·결과·검토를 게시합니다. 게시되지 않은 위임/도구 호출을 서버가 추정해서 채우지 않습니다. `agent_reported`는 담당 보고이며 독립 실행 증명이 아닙니다. 팀장 result는 조사·설계 완료일 뿐 복구 완료가 아닙니다. 상세의 변경 내역도 제안 요약이며 자동 코드 diff를 수집하지 않습니다.

`lab/.runtime/team-bridge/`에는 작업, 멱등 키, 작업별 게시 비밀, 세션 매핑이 저장됩니다. Git 제외 폴더이며 다른 사용자에게 공유하지 않습니다. OS 파일 권한의 강제 수준은 Windows 계정 ACL에 따릅니다. 최근 작업 최대 100건/작업당 이벤트 100건으로 제한하고 한도에 도달하면 접수를 막습니다. 자동 무손실 보관·삭제 UI는 이번 범위에 없습니다.

## 경계

- loopback 전용 바인딩, Host/Origin 검사, 브라우저 POST 세션 토큰, 크기 제한. 공개 배포용 사용자 인증이 아닙니다.
- 공개 이벤트는 고정 필드만 받으며 키·계정 주소·로컬 경로의 흔한 패턴을 가립니다. 모든 민감 정보 제거를 보장하는 필터는 아닙니다. **외부 공개 전 검토가 필요합니다.**
- 원문 대화·추론·도구 인자/결과 전체·기존 사적 기록을 조회하거나 게시하지 않습니다.
- 읽기 전용은 전달 프롬프트의 범위입니다. 기존 coding-agent 권한을 OS sandbox로 제한하는 기능은 아닙니다. 신뢰된 로컬 운영자만 사용합니다.
- 임의 shell/URL/SQL 실행 API, 자동 복구, 운영 변경 승인, 권한 자동 허용, 새 에이전트 생성은 제공하지 않습니다.
- 기존 Worker 판정·Cron·SLA·원격 DB와 연결하지 않습니다. PC를 끄면 이 로컬 브리지는 중단됩니다.

## 상시 서버로 옮길 때

1. Linux 서버에 코드·실습 Docker·Node·공식 Paseo daemon/CLI를 설치합니다. 제공자 로그인은 사용자가 그 서버에서 진행합니다.
2. 서버에서 기존 역할에 맞는 세션을 준비하고 로컬 bindings를 다시 설정합니다. 개인 PC의 인증 폴더·비밀 파일을 이미지에 넣지 않습니다.
3. 브리지를 비관리자 서비스로 실행하고 `Restart=on-failure` 같은 프로세스 감독과 영속 작업 디렉터리를 둡니다. 현재 CLI 어댑터는 Windows/POSIX를 분기합니다. Linux 실기동은 미검증입니다.
4. 웹 공개가 필요하면 접근 제어와 HTTPS가 먼저입니다. Worker에 외부로 나가는 상태 전송·작업 가져오기 프로토콜을 추가해야 합니다. 현재 구현에 원격 큐·수신 API가 있다고 가정하지 않습니다.

`team-bridge.service.example`은 Linux 사용자 서비스 초안입니다. Node·CLI 경로와 저장소 위치를 서버에 맞춰 바꾸고 Paseo daemon이 따로 실행 중인지 확인해야 합니다. 로그아웃 후 상시 실행을 위한 사용자 서비스 정책도 서버에서 결정해야 합니다. 파일을 설치하거나 `systemctl`을 실행한 것은 아니며 Linux 검증은 아직 없습니다.

이 단계에서는 서버 구매·상시 서버 배포·Worker 연결을 하지 않습니다. 개인 PC에서의 실제 팀 연동을 먼저 검증합니다.

검증: `node --test lab/tests/team-bridge.test.mjs`. CLI·파일 저장·인증·중복·공개 이벤트 경계를 대역으로 검사합니다. 실제 UI 렌더·375px·키보드 검수와 실제 팀 위임 실행은 별도 결과를 확인해야 합니다.
