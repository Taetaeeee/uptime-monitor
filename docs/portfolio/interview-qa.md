# 면접 질문·답변 포인트 (프로젝트 전체)

원칙: 확인한 것과 확인하지 못한 것을 구분해서 말합니다. 모르는 것은 "확인하지 못했습니다"로 답해도 됩니다.

## 설계

**Q1. 왜 장애를 2회 연속 실패로 판정했나요?**
- 일시적 흔들림 한 번에 알림이 울리면 알림 피로가 생기고, 그러면 진짜 장애가 묻힙니다.
- 대가는 감지가 최대 5분 늦어지는 것이고, 복구는 1회 성공으로 판정해 장애 시간이 부풀지 않게 했습니다.
- 실제 훈련에서 첫 실패 13:40, 판정 13:45(5분 뒤)로 확인했습니다.
- 측정(B-9)에서는 서버 지표 기준 1회→2회에서 오탐 약 79% 감소, 탐지율 40.7%p 감소였습니다. 이 데이터는 HTTP 점검이 아니라서 "2회가 최적"이라고는 못 합니다.

**Q2. 에이전트를 왜 바깥으로만 연결(push)하게 했나요?**
- 점검 대상 PC에 들어오는 포트를 열지 않아 공격 면이 줄어듭니다.
- 대가: 에이전트가 멈추면 보고가 끊기는데 지금은 이를 장애로 판정하지 못합니다. 알려진 한계이고, "N분간 보고 없음" 판정이 다음 과제입니다.

**Q3. 실제 데이터와 가짜 데이터를 어떻게 구분했나요?**
- 모든 기록에 출처(real/sample/simulator/replay)를 DB CHECK 제약으로 강제하고, 화면 배지와 보고서에 표시합니다.
- 실제와 가짜를 합친 숫자는 만들지 않습니다.
- 공개 데이터셋 재생은 `simulator`나 `real`을 재사용하지 않고 새 출처 `replay`를 만들었습니다. 어느 쪽으로 써도 화면이 거짓말이 되기 때문입니다.

**Q4. 재생 값은 어떤 판정 경로를 타나요?**
- 실측, 에이전트 보고, 재생이 모두 같은 `record.js` 경로를 탑니다. 규칙이 다르면 비교가 무의미해서입니다.
- 순수 계산과 DB 경로의 알림·장애 건수가 정확히 같은지 테스트로 비교합니다.

## 데이터·운영

**Q5. 마이그레이션 0008(출처 `replay` 추가)은 어떻게 안전하게 했나요?**
- SQLite는 CHECK 제약을 바꿀 수 없어서 테이블을 다시 만들었습니다.
- 자식→부모 순서로 지우고 부모→자식 순서로 복원하고, 적용 전에 백업했으며, 데이터가 든 DB에 적용하는 테스트로 검증했습니다.
- 컷오버 순서(백업 → 배포 → 적재 → 정리 → 확인)와 되돌리기 SQL을 미리 준비했습니다.

**Q6. 시간은 어떻게 다뤘나요?**
- 저장은 UTC, 하루·한 달 경계는 KST입니다. Cron이 정각보다 몇 초 늦어(실측 12초) 점검 시각을 5분 회차로 내림해 저장하고 집계했습니다.

**Q7. 로컬에서 `wrangler dev`를 못 썼다면 어떻게 테스트했나요?**
- 스마트 앱 컨트롤이 `workerd.exe`를 막았고, 보안 설정을 끄지 않았습니다.
- 대신 D1과 같은 SQLite(Node 내장)에 실제 마이그레이션을 적용한 가짜 D1로 Cron·API 흐름을 테스트하고 원격에서 확인했습니다.
- 한계: 가짜 D1이 실제 D1과 완전히 같다고는 보장하지 못합니다.

## 검증·정직성

**Q8. 판정 규칙 성능을 어떻게 검증했나요?**
- 규칙을 만든 데이터로 재면 낙관적이라, 임계값과 지표를 정할 때 쓰지 않은 서버·파일로만 공식 결과를 냈습니다.
- 시계열마다 앞 30%로 기준을 정하고 뒤 70%로 평가했습니다.
- 라벨을 보고 지표를 고르면 오탐이 0.81에서 0.06으로 좋아 보인다는 것(선택 편향)을 직접 보였습니다.
- 한계: 이상 구간 123건은 서로 독립이 아니고, NAB는 구간이 6개뿐이라 순위를 못 냅니다. 라벨 번호(1부터)는 가정입니다.

**Q9. 그 수치(탐지율 44.7%)로 이 서비스를 얼마나 잘 지키나요?**
- 말할 수 없습니다. 공개 데이터가 서버 지표와 센서 값이라 HTTP 점검 성능을 보여 주지 못합니다. README에도 그렇게 적었습니다.

**Q10. Keychats는 실제 사용자가 있는데 어떻게 점검했나요?**
- 채널·메시지는 건드리지 않았습니다. Keychats 쪽에 DB를 한 번 조회해 `ok`/`error`만 돌려주는 상태 확인 주소를 추가했고(응답에 사용자 정보 없음), 3초 제한을 걸었습니다.
- 채팅 전송·로그인·실시간 연결은 확인하지 않습니다. 가짜 메시지를 쌓는 종합 점검은 일부러 만들지 않았습니다.
