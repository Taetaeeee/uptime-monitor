## 혼동하기 쉬운 것

- **"실제 점검" 배지 ≠ 지금 점검 중.** 출처가 실제 점검이라는 뜻입니다. 장애 훈련 대상은 "점검 대기"이며 과거 기록만 남습니다.
- **장애 #41은 실제 서비스 장애가 아닙니다.** 에이전트 실제 모드로 내 PC의 테스트 포트를 일부러 끈 훈련이고, 복구됨·사후 보고서 있음 상태입니다. 훈련 대상 카드(점검 대기)와 장애 당시 이력은 따로 읽습니다.
- **30분 규칙은 화면 요약 기준입니다.** 마지막 점검이 30분을 넘은 실제 대상은 상태 띠·요약 카드에서 "정상"으로 세지 않지만, 서버가 장애로 판정한 것이 아닙니다. 서버 판정은 2회 연속 실패이고, 에이전트 무응답(`agent_silent`)은 대상별로 켜야 하며 아직 켠 대상이 없습니다.
- **탐지율 44.7%는 서버 지표 공개 데이터의 값**이며 이 서비스의 HTTP 점검 성능이 아닙니다.
- **재생(`replay`)은 다른 조직의 과거 기록**이지 이 회사의 실시간 데이터가 아닙니다. 라이선스는 README 표에서 확인할 수 있고 Backblaze는 MIT가 아닙니다.

## 검증하지 않은 것

- **라이브 확인(2026-11-13):** 주요 정적 파일·`/api/status`·`/api/incidents/41`·월간 보고서 API 응답과 `/report.html`·`/incident.html?id=41` 리다이렉트 정상, 상태 띠·요약 카드의 분모가 `/api/status`의 실제 활성 대상 수와 일치, 데스크톱 어두운/밝은 화면 확인. 배포 전에는 고정 응답 fixture와 Chrome CDP로 375px 모바일, 양 테마, 팝업 키보드, 보고서·장애 상세 print 미디어를 확인했습니다. **라이브에서의 375px·필터·팝업 조작, 실제 PDF 페이지 나눔은 확인하지 못했습니다.**
- 점검 대상 수나 서비스 수는 이 문서에 적지 않았습니다. 화면(`/api/status`)에서 확인해 주세요.
- 에이전트 무응답 감지를 켜서 하는 실제 환경 검증, 도메인 만료의 실제 조회(판정 로직만 있음), 점검 정밀도 5분 미만의 장애 감지는 없습니다.
