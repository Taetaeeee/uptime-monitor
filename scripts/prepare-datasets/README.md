# 데이터 준비 스크립트 (B-7c)

공개 데이터셋 원본을 받아 **재생용 SQL**(`seed/replay/`)로 가공합니다.
원본(수십 MB)은 저장소에 올리지 않고, 가공한 작은 조각(약 155KB)만 올립니다.

## 실행 순서 (프로젝트 폴더, Node 22 이상)

```powershell
node scripts/prepare-datasets/fetch.mjs     # 원본 내려받기 (약 120MB, 저장소 밖 폴더)
node scripts/prepare-datasets/analyze.mjs   # (선택) 어떤 지표·구간을 쓰는지 근거 표 출력
node scripts/prepare-datasets/build.mjs     # seed/replay/ 생성
```

- 원본 폴더 기본값: `..\uptime-monitor-data\raw` (`--raw <폴더>`로 바꿀 수 있음). 저장소 밖이라 실수로 커밋되지 않습니다.
- `fetch.mjs`는 코드에 적힌 파일만 받고, 받기 전에 크기를 확인하며, `SHA256SUMS.txt`에 해시를 남깁니다.
- `build.mjs`는 DB에 접속하지 않습니다. 같은 원본이면 항상 같은 파일이 나옵니다.
- Backblaze zip은 Windows 10 이상에 들어 있는 `tar`로 풉니다.
- 이 단계에서는 **원격 DB에 아무것도 올리지 않습니다.** 대상 등록과 적재는 B-7d에서 합니다.

## 만들어지는 파일 (`seed/replay/`)

| 파일 | 내용 |
|---|---|
| `datasets.sql` | 데이터셋 3종의 메타(이름·링크·라이선스·가공 방법·인용). 여러 번 실행해도 같은 결과(UPSERT) |
| `series-<대상 키>.sql` | 대상 5개의 시계열. 대상은 `check_key`로 찾고, 지우고 다시 넣으므로 여러 번 실행해도 같은 결과 |
| `manifest.json` | 대상 정의(서비스 이름, 간격, 길이, 지표 설명, 판정 규칙 제안). B-7d가 읽어 대상을 등록 |

## 무엇을 어떻게 가공했나

| 대상 | 데이터셋 | 가공 | 길이 |
|---|---|---|---|
| 그룹웨어·메일 / 사내 ERP / DB 서버 | SMD 장비 `machine-1-1`·`2-1`·`3-1` | 이상 구간이 많이 든 1주(1분 간격 10,080줄)를 5분 **최댓값**으로 줄임. 지표 1개 선택. 0~1 정규화 값을 %로 환산 | 2,016칸 × 3 |
| MES (생산관리) | NAB `machine_temperature_system_failure` | 라벨 창 2개와 앞뒤 12시간(2013-12-09 ~ 12-18)을 5분 간격 원본 그대로 | 2,432칸 |
| 파일서버·NAS 디스크 | Backblaze 2013 | 같은 모델 드라이브 8대(고장 2대 + 정상 6대)의 불량 섹터(`smart_5_raw`) 합계, 하루 1칸 | 60칸 |

## 알아 둘 점 (정직하게)

- **SMD의 지표는 이름이 공개되지 않았습니다.** "CPU"나 "메모리"라고 부르지 않고 "서버 지표 #N(익명·정규화)"로 표시합니다.
  값은 0~1로 정규화된 **상대값**이라, % 환산 값도 실제 사용률이 아닙니다.
- **지표 선택 편향:** SMD 지표는 "이상 구간을 가장 잘 잡고 헛경보가 적은 것"을 라벨을 보고 골랐습니다.
  그래서 이 지표로 판정 성능(B-9)을 재면 결과가 **낙관적**으로 나옵니다. B-9는 선택에 쓰지 않은 구간·장비로 평가합니다.
  (판정 기준값 자체는 라벨 없이 시리즈의 95·99% 지점으로 정했습니다.)
- **SMD 3-1(DB 서버)은 이상 구간 3개 중 1개만 장애로 잡힙니다.** 좋은 지표가 없는 장비도 있다는 뜻이고, 그대로 둡니다.
- **NAB 값의 단위는 원본이 밝히지 않았습니다.** "온도 센서 값"이라고만 적습니다.
- **Backblaze는 MIT가 아닙니다.** 공식 페이지의 자체 조건(출처를 Backblaze로 표기, 데이터 자체 판매 금지)을 `datasets.license`에 적었습니다.
  드라이브 시리얼 번호는 기록하지 않습니다.
- **Backblaze의 고장 2대는 같은 날 고장 났습니다.** 그래서 이상 표시가 있는 날은 1일입니다.
- **라이선스는 2026-11-12에 원본 저장소·페이지에서 직접 확인**한 것만 적었습니다.
  Loghub(연구·학술 목적)와 OTRF는 이번 범위가 아니고, SMD 논문 인용은 저장소 README에서 찾지 못해 비워 두었습니다.
